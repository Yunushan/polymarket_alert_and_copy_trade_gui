# Blockers

Last reviewed: 2026-08-23

This file documents why each market is either implemented, guarded, or stubbed. The project rule is: use official APIs, SDKs, documented endpoints, or protocol contracts only. Do not scrape private data, bypass authentication, or enable live trading/copy trading by default.

## Summary

- Polymarket, Kalshi, PredictIt, Crypto.com Predict/CDNA, Nadex/CDNA, Fanatics Markets/CDNA, FanDuel Predicts/OG, Blinq/Polymarket, Manifold, Metaculus, Good Judgment Open, SciCast archive, Myriad, Opinion, Gemini, Predict.fun, XO, Betfair, Limitless Exchange, SX Bet, Azuro, Augur, Omen, Gnosis Prediction Markets, Zeitgeist, Zeitgeist SDK / Markets, Zeitgeist Prediction Pools, Reality.eth Markets, Xmarket, Probable, Matchbook, DFlow, Context V2, Smarkets, Thales Market, MetaDAO, Seer, Hyperliquid, Trueo, Frenzy Finance, Hedgehog Markets, IBKR ForecastTrader, ForecastEx, CME event contracts, Prophet Exchange, PRDT Finance, Zetarium World, Lamas Finance, and BetMGM's partner Sports API are implemented adapters today.
- All other markets are present in config and GUI through verified-blocked adapters with exact blocker reasons.
- Live trading remains disabled by default for every market.
- Credentials must stay in `.env`, shell environment variables, OS keychain tooling, or external credential files. They must not be stored in `data/config.json`.

## 2026-05-26 Re-Audit Notes

Article 35 re-checked verified-blocked markets against current official pages and docs. No verified-blocked market was promoted in that pass because every candidate still failed at least one project rule: official production API availability, account/entitlement access, market-data licensing, documented order semantics, wallet/contract safety, or offline fixture coverage. Subsequent reviews promoted Drift BET, Frenzy Finance, Hedgehog Markets, Coinbase Prediction Markets, and Nadex/CDNA after their official public/contract surfaces and offline fixture coverage were validated. Drift inventory remains explicitly configured because its public OpenAPI contract has no stable market-list endpoint; Frenzy is limited to configured grid specs, `BetSettled` history, and dry-run intents because active quotes/oracle acknowledgements are off-chain; Hedgehog now includes a guarded externally signed `DepositV1` submission boundary while keeping signing and settlement operator-owned; Coinbase is limited to the public Kalshi venue alias because Coinbase-specific account execution APIs are not published; Nadex is limited to the documented Crypto.com Predictions API prediction-event data surface because account trading, DCM/FIX depth, and knock-out products are not automated.

Notable re-audit outcomes:

- `context_v2`: current Context v2 API documentation now publishes market, price, orderbook, activity, price-history, and signed-order endpoints. The adapter also normalizes activity trades and binary price-history points from offline fixtures. Activity preserves the upstream outcome label rather than inventing a BUY/SELL direction; history uses flat OHLC points with no fabricated volume. The adapter is guarded because API keys, wallet setup, chain eligibility, and current account/product availability remain external evidence gates.
- Historical review note (2026-05-26): `hyperliquid` documentation then described outcome asset IDs and `outcomeMeta` as testnet-only. The current HIP-4 review has promoted it to implemented with fixture-backed public metadata/orderbook coverage; live settlement and funded execution remain external gates.
- `thales_market`: official Thales docs describe API endpoints and contract integration. The adapter now covers public AMM reads, quote-backed paper orders, and a guarded externally signed transaction boundary; chain-specific AMM selection, collateral approval, wallet signing, and settlement remain operator-owned evidence gates.
- `smarkets`: official Smarkets API terms require account verification, application approval, a setup fee, pre-approved markets/limits, and written approval before platform data can be shared or distributed. Keep blocked without user-provided approval.
- `cme_prediction_markets`: the official IBKR Client Portal event-contract workflow now provides the broker/order path used by the adapter; CME data licensing and account entitlements remain external gates.
- Consumer app products such as Robinhood Prediction Markets, DraftKings Predictions, PrizePicks, and Underdog remain blocked because official public automation APIs and third-party integration terms are not published. BetMGM is the exception for read-only partner data: its official Sports API publishes fixture, market, option, and price data behind partner credentials, while order/account automation remains unsupported. Fanatics Markets is separately represented by the documented read-only CDNA alias below. Probo's official site now states that operations are closed, so it is also fail-closed rather than represented as an active integration target. Sporttrade separately states that all wagering ceased on 2026-05-25; both Sporttrade catalog entries remain verified blocked because the production product is no longer active.

## 2026-07-15 Incremental Re-Audit

Crypto.com Predict/CDNA was promoted from verified blocked to implemented after Crypto.com published the official Predictions Market Data API. The adapter uses the documented anonymous read-only event, search, contract, and price endpoints. It supports alerts and local dry-run paper orders, accepts an optional licensed `X-API-Key`, and records the published anonymous rate limits. Full orderbook depth, account activity, live orders, and copy trading remain unsupported because the official API is market-data-only. Personal non-commercial reads are anonymous; redistribution, commercial use, or model training requires a Market Data License.

## 2026-08-17 Incremental Re-Audit

Matchbook was promoted from verified blocked after its current developer centre was rechecked. The official API publishes event/market discovery, decimal-odds prices, runner offers/orderbooks, session login, `/v2/offers` submission, authenticated settled/current-bet reports, current-offer reads, wallet balance, and account profile. The adapter keeps reads fixture-backed, converts decimal odds to probabilities, requires a Matchbook session for account/live reads, and keeps live execution disabled unless the shared safety gates are explicitly enabled. Account eligibility, regional terms, API fees/limits, and real funded execution remain external evidence gates.

DFlow was promoted from verified blocked after its official Metadata/Trade API and current prediction-market recipe were rechecked. The adapter covers nested event/market discovery, settlement-account outcome mints, probability prices, public outcome-mint trade history, complementary YES/NO orderbooks, dry-run trade requests, and guarded submission of a wallet-signed transaction through an explicitly configured Solana RPC. API-key, Proof/KYC, jurisdiction, wallet, funded-balance, redemption, and asynchronous order-status evidence remain external gates.

Frenzy Finance was promoted on 2026-08-17 after its official Base/Base Sepolia contract deployments and `BetSettled` event shape were validated with offline fixtures. The adapter supports explicitly configured price-range grid specs, settlement history, alerts, and dry-run EIP-712 `BetIntent` previews. Active quotes/oracle acknowledgements remain off-chain and undocumented for this integration; wallet signing, orderbooks, live execution, and copy trading therefore remain fail-closed.

Coinbase Prediction Markets was promoted on 2026-08-17 as a read-only alias over Kalshi's official venue API. Coinbase's launch and help documentation identify Kalshi as the market-flow/outcome venue; the adapter therefore covers public discovery, contracts, prices, orderbooks, alerts, and local paper orders while keeping Coinbase-specific live execution and copy trading disabled.

FanDuel Predicts was promoted on 2026-08-21 as a read-only alias over the official Crypto.com OG Prediction Markets/CDNA data surface. FanDuel's current product and press-release pages state that its contracts are listed by both CME Group and Crypto.com derivatives exchanges; this adapter covers the OG/CDNA portion through the documented Predictions API, while CME-listed contracts remain available through the CME/IBKR adapter. FanDuel account execution, orderbook depth, and copy trading remain unsupported.

PRDT Finance's official legacy `Prediction` and `PredictionFactory` Solidity interfaces are represented by a fixture-backed, explicit-configuration adapter. It reads the configured Prediction contracts over EVM JSON-RPC, exposes the current bull/bear round and pool-share prices, and permits local paper intents only before the round lock timestamp. PRDT still does not publish a stable current factory/indexer inventory, so operators must supply and verify each deployed Prediction address; the adapter never guesses deployments or scrapes the consumer app. CLOB depth, wallet signing, live execution, settlement, and copy trading remain unsupported.

Context V2 was promoted from verified blocked after its current API reference was rechecked. The adapter covers market discovery, outcome-token contracts, price summaries, outcome-specific orderbooks, documented activity trades, binary price history, dry-run order payloads, and guarded submission of an externally signed order using a Context API key. Activity keeps Context's outcome-side semantics (YES/NO) and price history is represented as flat OHLC snapshots without synthetic volume. API-key, wallet approval/deposit, chain eligibility, settlement, and funded execution evidence remain external gates.

Prophet Exchange was promoted from verified blocked on 2026-08-17 after its official Market Data and Trading API references were rechecked. The adapter covers tournament/event/market discovery, nested and flat selection payloads, decimal-odds probability normalization, available-quantity quote books, local paper orders, and guarded authenticated `submit_order` requests using the documented market-maker shape. Partner approval, account/KYC/region eligibility, credentials, and funded execution remain external gates; the documented order path is BUY-only in this adapter.

Zetarium World and Lamas Finance were promoted on 2026-08-21 after their documented contract surfaces were rechecked. Zetarium uses the reviewed BSC `PredictionMarket` deployment; Lamas uses the official Solana Anchor `PricePredict` and `UpOrDown` programs. Both adapters are fixture-backed for discovery, prices, alerts, and paper intents, and accept only reviewed externally signed live transactions. Production deployment inventory, signing, settlement, and funded execution remain operator-owned gates; neither adapter exposes an orderbook or copy-trading surface.

Smarkets was promoted from verified blocked after its current v3 REST documentation was rechecked. The adapter covers event/market/contract discovery, quote-based orderbooks and prices, dry-run orders, and guarded session-authenticated order submission. Smarkets API application approval, written data-use permission, account eligibility, regional terms, and funded execution remain external gates.

Thales Market was promoted from verified blocked after its current official REST integration documentation and public Postman contract were rechecked. The adapter covers grouped/ungrouped AMM market discovery, positional contracts, public prices and buy-quote fallback, and local paper orders across the documented Optimism, Polygon, Arbitrum, and Base network IDs. Thales remains AMM-based rather than CLOB-based; wallet signing, collateral approval, settlement, and live on-chain execution stay explicitly disabled until contract transaction safeguards and funded evidence are added.

MetaDAO was promoted from verified blocked after its current official Futarchy DEX API documentation and public repository contract were rechecked. The adapter covers public `/api/tickers` DAO/token-pair discovery, bid/ask/last-price normalization, alerts, and local paper orders. The API is a read-only market-data feed; orderbook depth, Solana wallet signing, settlement, and live execution remain explicitly unsupported.

Seer was promoted from verified blocked after its current official serverless API documentation was rechecked. The adapter covers chain-qualified `markets-search` discovery, `get-market` hydration, outcome prices, alerts, and local paper orders. Seer's documented API is read-only; CLOB depth, wallet signing, settlement, and live execution remain explicitly unsupported.

Hyperliquid was promoted from verified blocked after its current HIP-4 outcome-market API documentation was rechecked. The adapter covers public `outcomeMeta` discovery, encoded outcome sides, `l2Book` prices/orderbooks, local paper orders, and guarded submission of complete externally signed exchange payloads. Wallet-scoped `userFills`/`userFillsByTime` history and the documented `openOrders`, `historicalOrders`, `clearinghouseState`, `spotClearinghouseState`, `portfolio`, and `subAccounts` account reads are exposed through the shared allow-listed account surface. Private-key handling, wallet signing, settlement, and funded execution remain external gates.

Trueo was promoted from verified blocked after its official Base deployment and contract documentation were rechecked. The adapter reads `TruthMarketManager` active markets, immutable `TruthMarket` fields, and documented Uniswap V3 pool prices through JSON-RPC, and supports alerts, local paper orders, and guarded submission of an externally signed transaction. CLOB depth, wallet signing, settlement, and funded execution remain external gates.

Zeitgeist SDK / Markets was promoted from verified blocked after confirming that the official SDK market-fetching contract uses the same documented Subsquid/indexer GraphQL market and asset schema. It has an explicit adapter class, configuration key, and independent fixtures so the catalog target is not silently treated as the primary Zeitgeist entry. It now shares the primary adapter's guarded, externally signed HybridRouter extrinsic boundary; signing, approvals, settlement, and CLOB depth remain external or unsupported.

IBKR ForecastTrader, ForecastEx, and CME event contracts were promoted after validating the official IBKR Client Portal event-contract workflow. The adapters use documented search/category-tree, strikes, instrument-info, marketdata/snapshot, historical OHLC, and account/orders routes, map conids and YES/NO rights deterministically, and require an authorized session, account/data entitlements, and explicit live-order gates.

Gnosis Prediction Markets was promoted after confirming that the current Gnosis prediction-market surface is Omen/Presagio. The adapter is an explicit market-scoped alias over the documented Omen FixedProductMarketMaker subgraph schema, with independent configuration, health diagnostics, fixtures, discovery, prices, alerts, paper-order coverage, and a guarded externally signed FPMM transaction boundary. CLOB depth, collateral approval, settlement, and copy trading remain unsupported by the underlying AMM surface.

Zeitgeist Prediction Pools was promoted after validating that the documented market-fetching GraphQL shape includes pool identifiers, pool status, weights, and asset prices. The adapter is an explicit pool-scoped alias with a separate endpoint key, pool-presence validation, independent fixtures, discovery, prices, alerts, paper-order coverage, and guarded forwarding of an externally signed HybridRouter extrinsic with reviewed pool metadata. Pool accounting, settlement, wallet signing, and CLOB depth remain unsupported.

Reality.eth Markets was promoted on 2026-08-17 after validating the official question subgraph schema. The adapter is intentionally read-only: it exposes question discovery, response-option listing, lifecycle status, and alert-compatible metadata through a configured GraphQL endpoint. Reality.eth does not expose traded prices, CLOB depth, paper orders, or exchange execution; those capabilities remain unsupported by the underlying oracle/question protocol.

## 2026-08-22 Nadex/CDNA promotion note

Nadex's current rules identify the exchange group as Crypto.com Derivatives
North America (CDNA), and Crypto.com publishes a documented Predictions Market
Data API with public event, contract, and price reads. The new `nadex` adapter is
therefore a read-only alias over that official data surface, with fixture-backed
discovery, contracts, prices, alerts, and local paper orders. This promotion is
deliberately limited to prediction-event data: it does not claim Nadex account
automation, DCM/FIX market-data depth, knock-out products, live orders, or copy
trading. Anonymous reads remain subject to the published personal-use and rate
limits; licensed API access is required for commercial redistribution or model
training.

## 2026-08-22 Blinq/Polymarket data-alias promotion note

Blinq's official product page says that its leverage layer trades Polymarket
markets, and its predictions page links that market experience. Because Blinq
does not publish a separate public market-data, leverage, wallet, or execution
API, the new `blinq` adapter is a narrow alias over Polymarket's documented
public data surface. It provides fixture-backed discovery, contracts, prices,
orderbooks, public price-history points, and authenticated read-only CLOB trade
history (explicit readonly/L2 headers are required), plus alerts and local
paper orders for the underlying markets. It does not automate Blinq leverage,
deposits, private account actions, live wallet execution, or copy trading.

## 2026-08-22 BetMGM promotion note

BetMGM's official partner Sports API publishes a versioned OpenAPI contract
for fixture discovery, market/option listing, and decimal/fractional/US odds.
The new adapter keeps the partner AccessId and AccessIdToken in the normal
credential resolver, normalizes odds to implied probabilities, and provides
fixture-backed local paper orders. The documented API has no order or account
activity endpoint, so live betting and copy trading remain unsupported.

## 2026-08-23 Good Judgment Open promotion note

Good Judgment Open is now represented through the documented Cultivate
Forecasts REST contract. The adapter covers question and answer discovery,
answer probabilities, irregular prediction-set history, local paper previews,
and a guarded forecast-submission boundary. The configured instance URL,
credentials, account/region eligibility, and any live evidence remain
operator-owned gates; submission is disabled by default and is not presented
as exchange order execution.

## Implementation Rules For Clearing A Blocker

1. Add or update an adapter using official/documented APIs only.
2. Add offline fixture tests for every endpoint parser and order/dry-run path.
3. Keep paper/dry-run mode as default.
4. Keep live trading disabled unless the user explicitly enables it in local config.
5. Never commit credentials, cookies, tokens, API keys, private URLs, IPs, or user data.
6. Update `README.md`, `data/config.example.json`, and this file when a blocker changes.
